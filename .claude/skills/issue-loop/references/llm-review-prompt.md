# LLM 리뷰 — 서브에이전트 프롬프트

CI `verify`가 **통과한 뒤에만** 돌린다. 실패한 코드를 심사할 이유가 없다 (DEC-10).
돌리는 주체는 **PR을 올린 세션**이다 — GitHub Actions job이 아니라서 워크플로 수정도 API 키 시크릿도 필요 없다.

## 왜 맥락을 끊는가

자기가 쓴 코드를 자기 기억으로 읽으면 자문이 아니라 자기 확인이 된다.
"이건 이래서 이렇게 한 거야"라는 설명이 머릿속에 남아 있으면, Issue 본문만 읽는 사람에게
그 코드가 어떻게 보이는지 알 수 없다. **구현 대화 맥락은 넘기지 않는다.**

## 입력

서브에이전트에게 주는 것은 이 다섯 개뿐이다.

| 입력 | 얻는 법 |
|---|---|
| Issue 본문 (종료 조건 C1~Cn · 5번 보호 영역) | `gh issue view <N>` |
| PR diff | `gh pr diff <PR번호>` |
| 그 Issue의 시도 기록 | `gh issue view <N> --comments` |
| SSOT §0 · `REQ-*` · `ARCH-*` | `docs/harness/01-ssot.md` (경로만 주고 읽게 한다) |
| 검증이 이미 본 것의 목록 | 아래 "안 보는 것" |

```
재고관리 PoC 저장소의 PR 하나를 심사한다. 일반 코드 리뷰가 아니라 **Issue 계약 심사**다.
구현 맥락은 일부러 주지 않았다 — Issue 본문만 읽은 사람의 눈으로 본다.

## 보는 것 (이 둘만)
1. 종료 조건 ↔ 구현 · 테스트 대조
   - 각 조건 C1~Cn 이 실제로 구현되었는가
   - 그 조건을 검증한다는 테스트가 **정말 그것을 검증하는가**
     (통과하지만 실제로는 불변식을 보지 않는 테스트, 픽스처가 조건을 비껴가는 테스트,
      경계값을 피해 간 테스트를 특히 본다)
   - `(수동)` 조건은 사람 몫이므로 "사람이 볼 것"에만 적는다
2. 보호 영역 침범 · 범위 밖 변경
   - Issue 5번과 SSOT §0 보호 영역(docs/harness/, SSOT §1·§2, 원문 01·06,
     검증 스크립트, 기존 테스트 기대값)을 건드렸는가
   - Issue 2번에 없는 변경이 diff에 있는가

## 안 보는 것
`npm run verify`가 이미 보는 것은 보지 않는다 — 타입 · 린트 · 아키텍처 B1~B6 ·
테스트 통과 여부 · 빌드. CI가 통과했으므로 전부 통과한 상태다.

## 출력
합격 · 불합격을 쓰지 않는다. 관찰만 적는다. 아래 형식 그대로, 다섯 줄 안팎으로.

## LLM 리뷰 · 시도 N/M · <sha>
- 종료 조건: C1 ✓ · C2 ⚠ <무엇이 어떻게 모자란지 · 파일:줄>
- 보호 영역: 위반 없음 | <파일 — 무엇을>
- 범위 밖 변경: 없음 | <파일 — 무엇을> — Issue에 없음
- 사람이 볼 것: <번호 · 항목> | 없음

지적할 게 없으면 없다고 쓴다. 매번 여러 건을 외치면 사람이 읽지 않게 되고,
그러면 자문이 아니라 소음이 된다.

---
## Issue #<N> 본문
<gh issue view 의 출력>

## 시도 기록
<gh issue view --comments 의 출력>

## PR #<번호> diff (sha <sha>)
<gh pr diff 의 출력>

## 규칙 원본
docs/harness/01-ssot.md §0(보호 정책 · 충돌 정책) · §1(REQ-*) · §2(ARCH-*) 를 직접 읽어라.
```

## 돌린 뒤

보고서를 `gh pr comment <PR번호> --body-file <파일>` 로 단다.

- 첫 줄의 `## LLM 리뷰`를 **지우지 않는다.** `gh` 코멘트는 사람의 GitHub 계정 이름으로 달려서,
  제목이 없으면 사람이 직접 쓴 말과 섞인다
- 리뷰는 **힘이 없다.** 지적이 있어도 루프를 막지 않고 시도를 쓰지 않는다 (⊕0).
  사람이 그 보고서를 보고 반려하면 **그때부터** 루프의 몫이다 (⊕1)
- 같은 diff에 매번 같은 말을 하지 않는다. 그래서 관문으로 쓰지 않는다 (04 §4)
- **보고서는 PR에, 그 보고서로 내린 결정은 Issue에** 남긴다
